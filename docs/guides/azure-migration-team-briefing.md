# SOHOBI 서버 이사 안내 (팀원용)

> 기준일: 2026-06-11 · 작성: PARK
> 5분이면 전체 상황을 이해할 수 있도록 쓴 문서입니다. 기술 배경이 없어도 읽을 수 있게 풀어 썼고, 더 깊은 내용이 필요하면 맨 아래 "더 읽기"를 참고하세요.

## 한 줄 요약

**SOHOBI 서비스를 "학교에서 빌려 쓰던 클라우드 계정"에서 "우리가 직접 결제하는 새 계정"으로 이사하는 중이며, 짐(데이터) 옮기기는 끝났고 손님(사이트 방문자) 안내만 남았습니다.**

## 왜 이사하나요?

지금까지 서비스는 학교 제휴 계정(학생용 Azure 구독)에서 돌아가고 있었습니다. 이 계정은:

- 언제 회수될지 우리가 통제할 수 없고 (졸업·정책 변경 등)
- 학생용 정책 때문에 예산 알림 같은 운영 기능에 제약이 있었습니다.

그래서 우리 명의의 새 계정을 만들고, 거기에 서비스 전체를 다시 지은 뒤 데이터를 옮기는 작업을 진행해 왔습니다. 이사 김에 **월 비용도 기존의 절반 이하로** 줄이도록 구조를 다시 잡았습니다.

## 지금 어디까지 왔나요?

이사를 "집 구하기 → 가구 들이기 → 짐 옮기기 → 손님에게 새 주소 알리기"에 비유하면, **3단계까지 끝났습니다.**

| 단계 | 비유 | 상태 |
|------|------|------|
| 1. 새 집 계약 | 새 클라우드 계정·결제 수단 준비 | ✅ 완료 |
| 2. 가구 들이기 | 서버·데이터베이스·AI 모델 등 똑같이 새로 구축 | ✅ 완료 |
| 3. 짐 옮기기 | 기존 데이터 전부 복사 | ✅ 완료 (아래 표) |
| 4. 손님 안내 | sohobi.net 방문자를 새 서버로 보내기 | ⏳ 남음 |

**옮긴 짐 목록** (2026-06-11 기준, 원본과 개수 일치 확인 완료):

| 데이터 | 규모 |
|--------|------|
| 상권·매출·부동산 데이터 (지역 분석에 쓰는 큰 데이터) | 표 11개, 약 313만 줄 |
| 사용자 세션·피드백·체크리스트 등 서비스 기록 | 약 4,700건 |
| 서버 운영 일지 (질문 기록·오류 기록) | 파일 3개 |

새 서버는 실제 질문을 던져보는 리허설(채팅 질문, 상권 분석 질문)까지 통과했습니다. 즉 **새 집은 완전히 살 수 있는 상태**입니다.

## 그럼 지금 sohobi.net 접속자는 어디로 가나요?

**아직 옛집(기존 서버)으로 갑니다.** 일부러 그렇게 두었습니다. 손님 안내(4단계)는 짧은 점검 시간을 잡고 한 번에 바꾸는 게 안전하기 때문입니다.

다행히 조사 결과, 안내판 교체가 생각보다 간단합니다. 도메인(주소 체계)을 건드릴 필요 없이 **설정값 하나만 바꾸고 화면(프런트엔드)을 다시 배포하면** 끝나고, 문제가 생기면 같은 방법으로 5분 안에 되돌릴 수 있습니다.

## 비용은 어떻게 되나요?

| 항목 | 금액 |
|------|------|
| 이사 전 (기존 계정, 월) | 약 13만원 |
| 이사 후 예상 (새 계정, 월) | **약 3.3~4.5만원** |
| 예산 알림 설정 | 월 6만원 초과 조짐이 보이면 자동 이메일 |

절감의 핵심은 (1) 안 쓰는 시간엔 서버가 자동으로 잠들어 요금이 안 나가는 구조, (2) 데이터베이스를 밤 12시~아침 8시에 자동으로 꺼두는 절전, (3) 비싸기만 했던 검색 서비스(월 10만원 정액)를 해지한 것입니다.

## 내가 올린 코드는 어느 서버에 반영되나요? (헷갈리기 쉬운 부분)

**main에 머지하면 지금까지처럼 sohobi.net(옛집)에 자동 반영됩니다.** 평소 개발 흐름은 아무것도 바뀌지 않았습니다.

| 내가 한 일 | 옛집 (sohobi.net) | 새집 |
|-----------|------------------|------|
| `frontend/` 수정 → main 머지 | ✅ 자동 배포 | ❌ 반영 안 됨 |
| `backend/` 수정 → main 머지 | ✅ 자동 배포 | ❌ 반영 안 됨 |
| `docs/` 수정 → main 머지 | 영향 없음 (사이트와 무관) | 영향 없음 |

새집에는 **자동 배포가 일부러 꺼져** 있습니다. 이사 완료 전에 검증 안 된 코드가 새 서버에 들어가는 사고를 막기 위해서입니다. 새집 반영은 PARK가 수동 버튼으로 진행합니다. (그래서 현재 새집 코드는 5월 28일 시점 스냅샷이고, 이사 당일에 최신으로 한 번에 맞춥니다.)

**데이터도 마찬가지로 한 방향입니다.** 6월 11일에 옛집 데이터를 통째로 복사해 갔지만, 그 이후 옛집에 쌓이는 새 기록(사용자 세션 등)은 새집에 실시간으로 넘어가지 않습니다. 이 차이는 이사 당일에 "그동안 쌓인 것만" 한 번 더 복사해서 맞춥니다.

## 새 서버에만 일부러 접속해 보고 싶다면

가능합니다. 두 환경의 주소 구분법부터:

| 환경 | backend 주소에 들어 있는 단어 |
|------|------------------------------|
| 옛집 (현재 라이브) | `livelybay` |
| 새집 | `politefield` |

**새집 backend 직접 주소**: `https://sohobi-backend.politefield-1cd9d809.koreacentral.azurecontainerapps.io`

- 살아 있는지 확인: 브라우저에서 위 주소 뒤에 `/health`를 붙여 열기. **첫 응답까지 30-60초 걸릴 수 있습니다** — 고장이 아니라, 손님이 없으면 서버가 잠들어 요금을 아끼는 구조라 깨어나는 시간입니다.
- API 호출: 기존과 같은 API 키 헤더(`X-API-Key`)를 쓰면 됩니다.
- **화면(UI)으로 보고 싶으면**: 새집용 화면은 아직 배포된 게 없습니다. 로컬에서 `frontend/` 폴더에 환경변수 `VITE_API_URL`을 위 새집 주소로 지정하고 `npm run dev`를 실행하면 "내 화면 + 새 서버" 조합으로 테스트할 수 있습니다.
- 새집에서 만든 질문·세션 기록은 테스트용입니다. 실서비스 기록과 섞이지 않으니 마음껏 테스트해도 됩니다.

## 그 밖에 혼동을 막기 위한 안내

- **로컬 `backend/.env`는 아직 옛집을 가리킵니다.** 로컬에서 backend를 돌리면 옛집 DB·옛집 AI 모델에 붙습니다. 이사 완료 후 새집 주소로 일괄 갱신할 예정이며, 그 전에 새집에 붙어 보고 싶으면 PARK에게 새집용 접속 정보를 요청하세요.
- **새집 DB는 외부 직접 접속이 막혀 있습니다.** 보안을 위해 Azure 내부에서만 접근되도록 잠가 두었습니다. 로컬 PC에서 DB 도구로 직접 붙어야 하면 PARK에게 IP 등록을 요청하세요 (1분 작업).
- **새집의 비밀 키는 옛집과 일부 다릅니다.** AI 모델 키 등은 새로 발급된 것이라, 옛집 키를 새집에 넣어도 동작하지 않을 수 있습니다. 필요한 키는 PARK에게 요청하세요.

## 팀원이 알아야 할 것 3가지

### 1. 밤 12시~아침 8시에는 지역 분석 기능이 잠들어 있습니다

절전을 위해 데이터베이스를 야간에 자동으로 꺼둡니다. 그 시간에 개발·테스트를 해야 하면 GitHub 저장소의 **Actions 탭 → "PG Nightly Stop/Start" → Run workflow → start** 를 누르면 몇 분 안에 켜집니다. (아침 8시 자동 기동은 그대로 유지됩니다.)

### 2. 새 환경의 설정을 화면(포털)에서 직접 바꾸지 마세요

새 환경은 모든 구성이 **코드로 기록**되어 있습니다 (저장소의 `infra/` 폴더). 포털에서 손으로 바꾼 설정은 다음 자동 배포 때 코드 기준으로 **되돌아가 버립니다** — 실제로 이번 주에 이 현상으로 새 서버가 잠시 멈춘 적이 있습니다. 인프라를 바꾸고 싶으면 코드 수정 + PR로 진행해 주세요. 방법을 모르면 PARK에게 요청하면 됩니다.

### 3. 법령 검색 기능은 CHOI 개인 계정에 연결되어 있습니다

법령 검색(legal)은 현재 CHOI가 만든 외부 검색 서버를 빌려 쓰는 구조입니다. CHOI 계정에 문제가 생기면 이 기능만 멈출 수 있어서, 장기적으로는 우리 데이터베이스 안에 검색 기능을 직접 넣는 방안(승인 완료, 착수 대기)이 잡혀 있습니다.

## 앞으로 남은 일정

| 순서 | 작업 | 영향 |
|------|------|------|
| 1 | 손님 안내 전환 (설정 1개 변경 + 재배포) | 짧은 점검 시간 1회, 이후 모든 트래픽이 새 서버로 |
| 2 | 1~2주 관찰 후 옛집(기존 계정 자원) 철거 | 없음. 철거 완료 시점부터 이중 비용 해소 |
| 3 | 법령 검색 자체 구축 (CHOI 계정 의존 해소) | 없음 (백그라운드 작업) |
